# เว็บไซต์สมาคมธุรกิจท่องเที่ยวเมืองเขลางค์นคร

## พัฒนาและตรวจสอบ

ใช้ Node.js 20 ขึ้นไป ไม่ต้องติดตั้ง npm dependencies

```sh
npm run build
npm test
python3 -m http.server 8000 --directory dist --bind 127.0.0.1
```

ต้องเปิดจาก `dist` หลัง build เพราะรายการกิจกรรมถูกสร้างที่ `content/events-index.json` ห้ามเปิดไฟล์ HTML ผ่าน file:// โดยตรง

## Cloudflare Pages

ตั้งค่า Framework preset: None, Build command: `npm run build`, Build output directory: `dist` และ Production branch: `main` (root directory คือราก repository) เปิด automatic deployments สำหรับ commit ใหม่บน main

เมื่อ CMS เผยแพร่ จะ commit JSON/รูปเข้า GitHub จากนั้น Cloudflare build รายการกิจกรรมและ deploy เว็บไซต์เป็นชุดเดียวกัน จึงไม่ต้องใช้ GitHub API จากเบราว์เซอร์ และไม่เจอปัญหาข้อมูลใหม่แต่ไฟล์ภาพยังไม่ deploy ต้องรอ deployment สำเร็จก่อนข้อมูลจะแสดง

## ผู้ดูแล

เปิด `/admin/` → เข้าสู่ระบบ GitHub → กิจกรรมและข่าวสาร → เพิ่มกิจกรรม เลือกรูปปก กรอกเรื่องย่อ เนื้อหา และภาพเพิ่มเติม ตรวจพรีวิวก่อนเผยแพร่

หน้าแรกแสดง 6 รายการเรียงตามวันที่จัดกิจกรรมล่าสุด หน้า Events แสดงทุกรายการ กิจกรรมเก่า 1–6 ถูกย้ายเป็น JSON พร้อมข้อความและแกลเลอรีแล้ว ลิงก์เก่าแบบ `?file=ชื่อไฟล์.md` ยังเปิดได้

OAuth Worker เดิมยังใช้ต่อ ผู้ใช้ต้องมีสิทธิ์เขียน repository หากเปลี่ยนโดเมนต้องตรวจ OAuth redirect/origin ที่ Worker และ GitHub OAuth App ด้วย ค่า `site_url` ใน admin/config.yml ยังใช้โดเมน pages.dev เดิม เนื่องจากยังไม่ทราบ custom domain

รายการชื่อ `test` ยังเก็บไว้เพื่อไม่ลบข้อมูลผู้ใช้ ผู้ดูแลสามารถลบผ่าน CMS หากไม่ต้องการเผยแพร่

พรีวิวหลังบ้านแสดงข้อความและภาพจากแบบฟอร์มที่ยังไม่บันทึก ส่วนลิงก์ดูบนเว็บไซต์จะแสดงเวอร์ชันที่ deploy แล้ว การเข้าสู่ระบบ OAuth และการเผยแพร่จริงต้องตรวจบน Cloudflare หลังนำการแก้ไขขึ้น GitHub

## รูปภาพใหม่ใน CMS

ช่องรูปปกและแกลเลอรีใช้ตัวอัปโหลดที่ประมวลผลในเบราว์เซอร์ก่อนส่งเข้าระบบ draft ของ Decap (ยังใช้ GitHub OAuth เดิม)

- แต่ละกิจกรรมมี `media_key` สร้างอัตโนมัติ เช่น `2026-10-29-event-<UUID>` วันที่คือวันที่สร้างโฟลเดอร์ ตามเวลาไทย ไม่เปลี่ยนตามการแก้ชื่อหรือวันที่จัดกิจกรรม
- รูปใหม่เก็บที่ `images/events/<media_key>/photo-<timestamp>-<UUID>.webp` ลดโอกาสชนชื่อ แม้ชื่อภาพต้นฉบับซ้ำกัน
- รับ JPG, PNG, WebP ไม่เกิน 20 MB / 60 ล้านพิกเซล ย่อด้านยาวไม่เกิน 1,920 px โดยไม่ขยายภาพเล็ก บีบอัด WebP เริ่มคุณภาพ 80% และลดคุณภาพ/มิติเมื่อเกินเป้าหมาย 500 KB ขนาดจริงขึ้นกับภาพ
- ถ้าภาพเล็กอยู่แล้วและแปลงแล้วใหญ่ขึ้น จะเก็บรูปแบบเดิมพร้อมชื่อใหม่ ภาพ PNG โปร่งใสยังคงโปร่งใส
- หากเลือกรูปที่มีเนื้อหาเหมือนกันซ้ำใน draft เดียว จะใช้พาธเดิมร่วมกัน เพื่อไม่เก็บไฟล์ซ้ำและไม่ทำให้พาธรูปช่องก่อนหน้าหายจากระบบ deduplicate ของ Decap
- รอข้อความ “พร้อมบันทึก” ก่อนกดเผยแพร่ รูปจะบันทึกพร้อมกิจกรรม รูปเก่าไม่ได้ถูกย้ายหรือลบทิ้ง กิจกรรมเก่าจะได้ media_key เมื่อเปิดแก้ไขและบันทึกครั้งต่อไป
- ระบบนี้ใช้กับช่องรูปปกและแกลเลอรี รูปที่อัปโหลดผ่านเมนู Media หรือแทรกตรงในเครื่องมือ Markdown ไม่ผ่านตัวประมวลผลนี้ ควรใช้ช่องแกลเลอรีสำหรับรูปบรรยากาศ
- การนำรูปออกจากช่องไม่ได้ลบไฟล์เก่าหรือประวัติ Git โดยอัตโนมัติ

Browser smoke test ใช้ backend `test-repo` ในเครื่อง ไม่เรียก GitHub และไม่เผยแพร่เนื้อหาทดสอบจริง ต้องมี Python packages `playwright`, `PyYAML`, `Pillow` และ Chromium ที่ `/usr/bin/chromium` ดาวน์โหลดและแตกแพ็กเกจทางการ `decap-cms@3.17.3` แล้วรัน:

```sh
python3 tests/browser_upload.py --cms-dist /path/to/decap-cms/package/dist
```

## ปฏิทินกิจกรรม Google Calendar

หน้า `calendar.html` และคอลัมน์กำหนดการบนหน้าแรกฝัง Google Calendar โดยตรง ไม่ใช้ API key และไม่คัดลอกรายการจาก Google ลง GitHub กิจกรรมประจำ การเลื่อนวัน และการยกเลิกจะแสดงตามข้อมูลของ Google เมื่อรีเฟรช โดยอาจมีความล่าช้าจาก cache ของ Google

ผู้ดูแลเพิ่ม/แก้กำหนดการที่ Google Calendar ส่วนข่าวและภาพหลังงานยังใช้คอลเลกชันกิจกรรมใน `/admin` ตามเดิม

การตั้งค่า Google Calendar:

1. ใน Google Calendar บนคอมพิวเตอร์ เลือกปฏิทินสมาคม → การตั้งค่าและการแชร์
2. ตั้งเขตเวลาเป็นกรุงเทพฯ และในสิทธิ์การเข้าถึงกิจกรรม เปิดให้สาธารณะดู “รายละเอียดกิจกรรมทั้งหมด” หากบัญชีองค์กรไม่อนุญาต ต้องให้ผู้ดูแล Google Workspace เปิดสิทธิ์ก่อน ใส่เฉพาะกำหนดการที่เปิดเผยได้ในปฏิทินนี้
3. แชร์สิทธิ์ “แก้ไขกิจกรรม” ให้บัญชี Google ของผู้ดูแลแต่ละคน การแก้กำหนดการในปฏิทินไม่จำเป็นต้องมีสิทธิ์ GitHub
4. Calendar ID ตั้งไว้ใน `content/settings/calendar.json` แล้ว เปลี่ยนได้จาก `/admin` → ตั้งค่าเว็บไซต์ → Google Calendar ของสมาคม ช่องนี้รับ ID, ลิงก์แชร์ `?cid=…` หรือลิงก์ฝัง `?src=…` ได้ เว้นว่างเพื่อพักการแสดงผล การเปลี่ยนค่าตรงนี้ต้องรอ Cloudflare deploy
5. เปิดหน้าเว็บในหน้าต่างไม่ระบุตัวตนเพื่อตรวจว่าผู้ที่ไม่ได้ล็อกอินเห็นกำหนดการได้

ปุ่มติดตามเปิด Google Calendar เพื่อให้สมาชิกเพิ่มปฏิทินเข้าบัญชีตนเอง หากทำบนมือถือไม่ได้ ให้เพิ่มจากคอมพิวเตอร์ก่อน แล้วเปิดแอป Google Calendar ด้วยบัญชีเดียวกันและเลือกแสดงปฏิทินสมาคม การตั้งแจ้งเตือนเป็นของสมาชิกแต่ละคน

หน้าแรกใช้มุมมอง Agenda ของ Google ในกรอบเลื่อนได้ จำนวนรายการที่เห็นขึ้นอยู่กับความยาวข้อมูลและขนาดจอ ไม่มีการตัดจำนวนให้เหลือ 3 หรือ 5 รายการแบบรายการที่เรนเดอร์เอง หน้าปฏิทินเต็มเลือกดูรายเดือนหรือ Agenda ได้ บนมือถือเริ่มด้วย Agenda เพื่อให้อ่านง่าย

ทดสอบส่วนหน้าแบบจำลองการตอบกลับ iframe ของ Google (ไม่ตรวจสิทธิ์สาธารณะหรือกิจกรรมจริง):

```sh
npm run build
python3 tests/browser_calendar.py
```

ต้องมี Playwright และ Chromium ที่ `/usr/bin/chromium` หาก Google iframe ถูกบล็อก ผู้ใช้มีลิงก์เปิด Google Calendar โดยตรง การทดสอบจากเครื่องพัฒนาครั้งนี้ถูกนโยบายเครือข่ายบล็อก `calendar.google.com` จึงต้องตรวจสิทธิ์สาธารณะบนเว็บจริงเพิ่มเติม
